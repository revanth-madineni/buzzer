## The problem: a fresh upload can't be fetched straight away (§4.4)

§4.4 says the upload handlers should leave the database commit to `get_db`. On the FastAPI in the container (0.142), `get_db` commits only after the 201 has been sent. So a client that fetches the image as soon as the upload returns can get a 404, because the row isn't saved yet. In a loop of 60 uploads, each followed immediately by a GET, 34 of the GETs returned 404. The editor would hit this every time: upload, then immediately draw the image.

Adding `await db.commit()` inside both upload handlers fixes it: 0 failures in 100 tries, and the 19 integration tests passed 3 runs in a row. The existing admin create handlers already commit this way. That fix is in the working tree now.
